# 開發版數學與規則決策

版本 `goldenhen-development-v1`。2026-10-27 使用者明確回答「授權建立開發版規則」。以下僅用來完成可玩的開發流程，不覆寫原始 Excel 的 Q-01～Q-10，不作正式 RTP 或認證主張。

- 每軸從設定輪帶均勻抽一個起點，連續取五格，index 0／4 為上下緩衝，1～3 可視。各軸獨立，使用 `crypto/rand.Int`。fakeStrips 只供 client 轉動顯示。
- 243 ways：從最左輪起連續至少三輪；同 symbol 僅取最長一筆。派彩 = paytable[連數−1] × 線注 × 每輪匹配格數乘積。不同 symbol 可共用 Wild；必須至少有一顆該實際 symbol。純 Wild 不獨立派彩，Wild 不替代 Scatter。
- 一般／黃金 ID 分別計獎，不混連。抽樣後依線注 100／250／500／1000 解鎖鞭炮、元寶、玉佩、金雞；保留已知 ID 對應 18→13、17→12、16→11、15→10。這些門檻是開發值。
- paytable 保存在 JSON，未沿用規格明確禁止的測試 `[0,0,10,20,50]`。沒有最大贏分截斷；全部是整數乘法。啟動時驗證最壞派彩，動作抽樣前檢查安全整數容量，避免因抽到大獎才拒絕／重抽。
- Scatter 按從第一輪起連續的含 Scatter 輪數計算，至少三輪給 6 次 FG，同輪多顆只算一輪；Scatter 不另派彩，ways 可同時派彩。FG 每次再觸發加 2，整段總局數上限 20。FG 與主遊戲使用各自設定的輪帶。
- FG 觸發時凍結線注與黃金 state。init 動作只開始，不消耗局數；後續每次 NEXT_FEVER 消耗一局。最後一局再加局仍留在 FG；達總局數上限後不再加。
- JP：可視盤面至少一顆 Wild、黃金 state≥2 時，每局做一次 30000／1000000 的觸發抽樣；主遊戲及 FG 都適用。state=1 禁止觸發。壓暗的獎級不得開出。
- state=2 的 JP 在開始時直接支付 MINI；state≥3 預先生成 18 顆私有內容，在已開放獎級間均勻抽樣。逐次點選只揭露，不改變內容；同一格新 ID 重點回 `ALREADY_PICKED`。第三個同色時支付一次。
- JP 金額採觸發時總押注倍數：GRAND 1000、MAJOR 200、MINOR 50、MINI 10；屬固定倍數測試獎，不是累積獎池。尚未集滿的點選 lastWin=0。
- 同局 FG＋JP 時 JP 先進行，再進 FG。FG 非末局或末局加局觸發 JP 時，JP 完成回剩餘 FG；末局沒有加局則 JP 完成回 Main。
- totalWin 是本次主遊戲及其後特殊遊戲鏈的累計；每個 lastWin 在該次交易只入帳一次。START_GAME 與 JP 點選不重複入帳。新主遊戲 spin 重置 totalWin。
- winType 使用展示倍數界線 1、5、10、25、50、100；無獎為 0，小於 1 倍正獎為 1，其餘依序 2～7。它不參與派彩。

初始餘額 100000000；線注／總注成對為 1000／50000、500／25000、100／5000。1 信用點 = 10000 原始單位。這些錢包與投注值可換設定。

正式模型後續需補期望值、波動與完整回合驗證。此次 50 局是傳輸與帳務整合測試，不能當成 RTP 評估。
